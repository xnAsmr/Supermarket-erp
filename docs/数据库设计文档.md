## 1. 设计概述

### 1.1 数据库创建

```sql
CREATE DATABASE IF NOT EXISTS `supermarket_erp`
  DEFAULT CHARACTER SET utf8mb4
  DEFAULT COLLATE utf8mb4_general_ci;

USE `supermarket_erp`;
```

### 1.2 设计原则

- **多租户隔离：** 采用共享数据库 + `tenant_id` 字段隔离方案，所有业务表包含 `tenant_id` 字段
- **软删除：** 所有业务表使用 `deleted` 字段实现软删除，保留历史数据
- **审计字段：** 所有表包含 `create_time`、`update_time`、`create_by`、`update_by` 审计字段
- **雪花算法：** 主键使用 BIGINT 类型，由后端雪花算法生成
- **金额字段：** 统一使用 DECIMAL(10,2)，单位为元

### 1.2 数据隔离策略

| 隔离级别 | 适用表 | 说明 |
|----------|--------|------|
| **租户级** | 商品、分类、品牌、供应商、会员、库存、采购 | WHERE tenant_id = ? |
| **门店级** | 订单、收银流水、支付配置 | WHERE tenant_id = ? AND store_id = ? |
| **系统级** | 租户、菜单、字典、系统日志 | 无隔离 |

### 1.3 公共字段规范

所有业务表必须包含以下公共字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | BIGINT | 主键，雪花算法生成 |
| `tenant_id` | BIGINT | 租户ID（系统级表除外） |
| `create_time` | DATETIME | 创建时间 |
| `update_time` | DATETIME | 更新时间 |
| `create_by` | BIGINT | 创建人ID |
| `update_by` | BIGINT | 更新人ID |
| `deleted` | TINYINT | 软删除：0-未删除 1-已删除 |

## 2. 命名规范

### 2.1 表名规范

| 模块 | 前缀 | 示例 |
|------|------|------|
| 系统管理 | `sys_` | `sys_user`, `sys_role` |
| 租户管理 | `sys_` | `sys_tenant`, `sys_store` |
| 商品管理 | `pms_` | `pms_product`, `pms_category` |
| 库存管理 | `wms_` | `wms_stock`, `wms_purchase_in` |
| 订单管理 | `oms_` | `oms_order`, `oms_order_item` |
| 会员管理 | `ums_` | `ums_member`, `ums_member_level` |
| 报表统计 | `rpt_` | `rpt_daily_sales` |

### 2.2 字段命名规范

- 使用小写字母 + 下划线命名（snake_case）
- 主键统一命名为 `id`
- 外键命名为 `表名_id`（如 `product_id`, `tenant_id`）
- 布尔字段使用 `is_` 前缀（如 `is_deleted`, `is_enabled`）
- 时间字段使用 `_time` 后缀（如 `create_time`, `pay_time`）
- 状态字段使用 `_status` 后缀（如 `order_status`, `pay_status`）

### 2.3 索引命名规范

| 类型 | 命名格式 | 示例 |
|------|----------|------|
| 主键 | `PRIMARY` | `PRIMARY KEY (id)` |
| 唯一索引 | `uk_表名_字段` | `uk_product_barcode` |
| 普通索引 | `idx_表名_字段` | `idx_product_category_id` |
| 联合索引 | `idx_表名_字段1_字段2` | `idx_order_tenant_store` |

## 4. 系统管理模块

### 4.1 租户信息表（sys_tenant）

系统级表，存储所有租户（超市）基本信息。

```sql
CREATE TABLE `sys_tenant` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `tenant_no` VARCHAR(32) NOT NULL COMMENT '租户编号',
  `tenant_name` VARCHAR(100) NOT NULL COMMENT '租户名称（超市名称）',
  `contact_name` VARCHAR(50) NOT NULL COMMENT '联系人姓名',
  `contact_phone` VARCHAR(20) NOT NULL COMMENT '联系人电话',
  `contact_email` VARCHAR(100) DEFAULT NULL COMMENT '联系人邮箱',
  `logo` VARCHAR(500) DEFAULT NULL COMMENT '企业Logo',
  `address` VARCHAR(200) DEFAULT NULL COMMENT '地址',
  `license_no` VARCHAR(50) DEFAULT NULL COMMENT '营业执照号',
  `plan_type` TINYINT NOT NULL DEFAULT 1 COMMENT '套餐类型：1-基础版 2-专业版 3-企业版',
  `max_stores` INT NOT NULL DEFAULT 1 COMMENT '最大门店数',
  `max_users` INT NOT NULL DEFAULT 5 COMMENT '最大用户数',
  `expire_time` DATETIME NOT NULL COMMENT '到期时间',
  `status` TINYINT NOT NULL DEFAULT 1 COMMENT '状态：0-禁用 1-正常 2-已到期',
  `admin_user_id` BIGINT DEFAULT NULL COMMENT '管理员用户ID',
  `remark` VARCHAR(500) DEFAULT NULL COMMENT '备注',
  `create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `create_by` BIGINT DEFAULT NULL COMMENT '创建人',
  `update_by` BIGINT DEFAULT NULL COMMENT '更新人',
  `deleted` TINYINT NOT NULL DEFAULT 0 COMMENT '删除标志：0-未删除 1-已删除',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_tenant_no` (`tenant_no`),
  KEY `idx_status` (`status`),
  KEY `idx_expire_time` (`expire_time`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci COMMENT='租户信息表';
```

## 7. 库存管理模块

### 7.1 库存表（wms_stock）

租户+门店级表，记录每个门店每个商品的库存。包含仓库库存（warehouse_quantity）和货架库存（shelf_quantity），采购入库增加仓库库存，出库从仓库移到货架，POS销售从货架扣减。

```sql
CREATE TABLE `wms_stock` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `tenant_id` BIGINT NOT NULL COMMENT '租户ID',
  `store_id` BIGINT NOT NULL COMMENT '门店ID',
  `product_id` BIGINT NOT NULL COMMENT '商品ID',
  `warehouse_quantity` DECIMAL(10,2) NOT NULL DEFAULT 0.00 COMMENT '仓库库存',
  `shelf_quantity` DECIMAL(10,2) NOT NULL DEFAULT 0.00 COMMENT '货架库存（可售）',
  `avg_cost` DECIMAL(10,2) NOT NULL DEFAULT 0.00 COMMENT '平均成本价',
  `create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_tenant_product_store` (`tenant_id`, `product_id`, `store_id`),
  KEY `idx_tenant_id` (`tenant_id`),
  KEY `idx_store_id` (`store_id`),
  KEY `idx_product_id` (`product_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci COMMENT='库存表';
```

**库存字段说明：**
- `warehouse_quantity`：仓库库存，采购入库增加，出库减少
- `shelf_quantity`：货架库存（可售），销售出库增加，POS销售减少
- `pending_in_quantity`：待入库数量（动态计算），= 状态0(草稿)+1(已审核)的入库单明细数量之和

**库存流转说明：**
- 采购入库：`warehouse_quantity += 入库数量`
- 销售出库（type=1）：`warehouse_quantity -= 出库数量`，`shelf_quantity += 出库数量`（仓库→货架）
- 调拨/报损/其他出库（type=2/3/4）：`warehouse_quantity -= 出库数量`
- 撤销销售出库：`warehouse_quantity += 数量`，`shelf_quantity -= 数量`（货架→仓库）
- 撤销其他出库：`warehouse_quantity += 数量`
- POS 销售：`shelf_quantity -= 销售数量`
- POS 退款：`shelf_quantity += 退款数量`
- 库存调整（IN）：`warehouse_quantity += 调整数量`
- 库存调整（OUT）：`warehouse_quantity -= 调整数量`
- 待入库数量（动态计算）：= status 0(草稿) + 1(已审核) 的入库单明细数量之和

## 12. 关键设计决策

### ADR-001: 库存扣减方式

**决策：** 下单时扣减库存（悲观锁 + 数据库行锁）

```sql
UPDATE wms_stock
SET quantity = quantity - #{quantity},
    update_time = NOW()
WHERE product_id = #{productId}
  AND store_id = #{storeId}
  AND quantity >= #{quantity}
```

通过检查 `affected_rows` 判断是否成功。

### ADR-002: 订单号生成规则

**格式：** `yyyyMMddHHmmss` + `{3位门店编号}` + `{4位序列号}`

**示例：** `202608301430250010001`

### ADR-003: 软删除策略

所有业务表使用 `deleted` 字段实现软删除，保留历史数据，支持数据恢复和审计。

### ADR-004: 商品搜索策略

多字段模糊搜索 + Caffeine 热门商品缓存 + 前端本地索引。搜索匹配优先级：

1. 条形码精确匹配
2. 拼音首字母精确匹配
3. 商品名称精确匹配
4. 商品名称模糊匹配
5. 分类 + 名称组合匹配

### ADR-005: 记账式支付决策

记账式支付，收银员手动选择支付方式并输入金额。不接入第三方支付。核心原则：

1. 支付记录不可篡改
2. 一笔订单支持多种支付方式（组合支付）
3. 收银流水独立记录
4. 完整审计轨迹
5. 前端 + 后端双重校验

### ADR-006: 缓存架构决策

三层缓存：浏览器 IndexedDB + 服务端 Caffeine 本地缓存 + MySQL 数据库。**单店场景不引入 Redis。** 演进路径：多节点或多门店连锁部署时引入 Redis。

### ADR-007: 多租户架构决策

共享数据库 + `tenant_id` 字段隔离。

- **成本：** 比独立数据库低 60-70%
- **维护：** 单数据库，备份恢复简单
- **扩展：** 新租户仅需插入数据
- **隔离：** 严格的 tenant_id 隔离

实现方式：MyBatis-Plus 租户拦截器自动为 SQL 添加 tenant_id。

演进路径：V1.6 共享数据库（当前） → V2.0 大租户可选独立数据库 → V3.0 微服务
